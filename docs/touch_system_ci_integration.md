1. **GitHub Actions CI** - Automated checks on every push/PR

## CI/CD Integration

### Main CI Pipeline (`.github/workflows/ci.yml`)

The `doc-build-touch` job runs on every push and PR:

**What It Does:**
1. Scans documentation dependencies
2. Checks doc freshness (warns if stale)
3. Analyzes stale docs by tier
4. Shows auto-freshen plan (dry-run)
5. Scans build tree dependencies
6. Checks build artifact freshness
7. Generates touch system report

**Artifacts:**
- `touch-system-report` - Full staleness analysis

**Failure Behavior:**
- Currently **warns only** (doesn't fail build)
- Uncomment `exit 1` to enforce freshness

```yaml
# In .github/workflows/ci.yml
doc-build-touch:
  runs-on: ubuntu-latest
  needs: linux
  steps:
    - name: Scan documentation dependencies
    - name: Check doc freshness
    - name: Analyze stale docs
    - name: Auto-freshen Tier 1 docs (dry-run)
    - name: Scan build tree dependencies
    - name: Check build artifact freshness
    - name: Generate touch system report
```

### Auto-Freshen Workflow (`.github/workflows/doc_freshen.yml`)

Runs every 6 hours or on manual trigger:

**What It Does:**
1. Scans docs and checks for staleness
2. Auto-freshens Tier 1 docs (dates, broken refs)
3. Generates AI prompts for Tier 2 docs
4. Creates PR with changes

**Permissions:**
- `contents: write` - To commit changes
- `pull-requests: write` - To create PRs

**Output:**
- Automated PR titled "Auto-freshen stale documentation"
- AI update prompts uploaded as artifacts

**Configuration:**
```yaml
schedule:
  - cron: '0 */6 * * *'  # Every 6 hours

workflow_dispatch:  # Manual trigger available
```

**PR Contents:**
- Auto-freshened Tier 1 docs
- AI prompts for Tier 2 manual review
- Summary of changes made

## Pre-commit Integration

### Installation

The touch system is integrated via `.pre-commit-config.yaml`:

```bash
# Install pre-commit framework
pip install pre-commit

# Install hooks
pre-commit install

# Run manually on all files
pre-commit run --all-files
```

### What Gets Checked

When you commit `.md` files:

1. **Documentation scan** - Rebuilds metadata
2. **Freshness check** - Detects stale docs
3. **Warning display** - Shows what's stale
4. **Recommendations** - Suggests actions

**Behavior:**
- Currently **warns only** (allows commit)
- Shows top 20 stale docs
- Provides fix commands

**To Bypass:**
```bash
git commit --no-verify
```

### Pre-commit Hook Configuration

```yaml
# .pre-commit-config.yaml
- id: doc-touch-check
  name: Check documentation freshness
  entry: ./scripts/pre_commit_doc_touch.sh
  language: script
  pass_filenames: false
  files: '\.md$'
  stages: [commit]
```

## Enforcement Levels

### Current Configuration (Warn Only)

- CI job **succeeds** even with stale docs
- Pre-commit hook **allows** commits
- Warnings visible in logs

### Strict Enforcement (Optional)

To enforce freshness:

**In CI (`.github/workflows/ci.yml`):**
```yaml
- name: Fail if critical docs are stale
  if: steps.doc_check.outputs.STALE_DOCS == 'true'
  run: |
    echo "::error::Stale documentation detected"
    exit 1  # Uncomment to enforce
```

**In Pre-commit (`scripts/pre_commit_doc_touch.sh`):**
```bash
# Uncomment to enforce freshness:
exit 1
```

## Troubleshooting

### Pre-commit Hook Not Running

```bash
# Reinstall hooks
pre-commit uninstall
pre-commit install

# Verify installation
pre-commit run --all-files
```

### CI Job Failing

**Check:**
1. Python 3 available
2. Scripts executable (`chmod +x scripts/*.py scripts/*.sh`)
3. Dependencies installed (none required beyond Python 3)

**Logs:**
- Check `touch-system-report` artifact
- Review job output in GitHub Actions

### Auto-Freshen PR Not Created

**Possible Causes:**
1. No stale docs (nothing to freshen)
2. Tier 1 updates made no changes
3. GitHub token permissions insufficient

**Verify:**
- Run locally: `make doc-freshen`
- Check workflow permissions in GitHub

Edit `.github/workflows/doc_freshen.yml`:

```yaml

  - cron: '0 0 * * *'  # Daily at midnight
  # or
  - cron: '0 */12 * * *'  # Every 12 hours
```

In `scripts/doc_freshen.py`:

```python
# Lower threshold for more aggressive auto-freshening
def _is_simple_reference_sync(self, changes):
    return confidence >= 0.8  # Changed from 0.95
```

## Best Practices

### For Developers

1. **Run checks before commits:**
   ```bash
   make touch-check-all
   ```

2. **Auto-freshen simple updates:**
   ```bash
   make doc-freshen
   ```

3. **Review AI prompts for complex updates:**
   ```bash
   ls docs/ai_freshening/
   cat docs/ai_freshening/my_doc_prompt.md
   ```

### For Maintainers

1. **Review auto-freshen PRs promptly**
   - Verify date updates are reasonable
   - Check cross-reference fixes

2. **Monitor CI warnings**
   - Stale critical docs should be addressed
   - Large-scale staleness indicates systemic issues

3. **Periodic metadata rebuilds**
   - After major refactors: `make doc-scan`
   - After dependency changes: `make build-scan`
